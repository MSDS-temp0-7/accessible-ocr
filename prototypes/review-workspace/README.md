# 읽기·교차 검수 화면 시제품

Windows 앱에 적용하기 전에 HTML/CSS/JavaScript로 검토하는 화면입니다. 실제 OCR 결과 대신 직접 작성한 3페이지 예시(본문·표·그래프·악보)를 사용합니다. 외부 라이브러리와 네트워크 API 호출은 없습니다.

## 실행

이 폴더의 `index.html`을 Edge 또는 Chrome으로 열면 됩니다. 설치·빌드·OCR 서버·Ollama는 필요하지 않습니다. 파일로 열었을 때 브라우저 정책에 따라 수정 내용의 재접속 보관이 제한될 수 있습니다. 이 경우 검수 기록을 JSON으로 저장하세요.

개발 중 로컬 서버로 확인하려면 저장소 루트에서 실행합니다.

```powershell
.\.venv\Scripts\python.exe -m http.server 8770 --bind 127.0.0.1 --directory prototypes/review-workspace
```

브라우저에서 `http://127.0.0.1:8770`을 엽니다. 이 서버는 정적 파일만 제공하며, 실제 OCR API 서버와 별개입니다.

## 피드백 반영

| 피드백 | 시제품에서의 구현 |
|---|---|
| 리더로 시작 | 새로 열 때 읽기 모드로 진입. 자동 음성 재생은 하지 않음 |
| 텍스트 클릭 → 이미지 하이라이트 | 검수 모드에서 결과 제목·본문 클릭 시 동일 번호의 원본 영역 강조 |
| 교차 검수 편의 | 결과와 원본을 나란히 배치. 이미지 영역 클릭 시 결과로 포커스 이동. 좁은 화면에서는 세로 배치 |
| 인식 결과 화면 개선 | 문서 개요, 유형·상태, 현재 페이지 검색, 원본 표시, 검수 도구 분리 |
| 빠르게 읽고 검수 | 제목·영역 탐색, 다음 검수 필요 항목, 키보드 완료·이동, 표의 행·열 읽기, 악보의 마디별 상세 읽기 |
| 저시력 사용 | 본문 글자 크기 100~200%, 고대비, 선택 테두리와 번호, 키보드 포커스 표시 |

‘리더로 시작’은 **읽기 모드로 먼저 진입한다**는 가정입니다. 스크린리더의 음성을 강제로 시작하는 기능은 아닙니다.

## 팀과 함께 확인할 순서

1. 처음 화면이 읽기 모드인지 확인합니다.
2. **검수 모드**를 누릅니다.
3. 1페이지의 **함께 읽는 사람들이 늘었습니다**를 누릅니다. 오른쪽 원본의 2번 영역이 강조됩니다.
4. 원본의 3번 표 영역을 누릅니다. 왼쪽 결과의 표 항목에 포커스가 이동합니다.
5. **다음 검수 필요 항목**으로 페이지를 넘나들며 이동합니다.
6. 본문의 ‘증기했습니다’를 **내용 수정**에서 ‘증가했습니다’로 고칩니다. 수정 저장과 확인 완료는 별도입니다.
7. **확인 완료 · 다음**을 누르면 완료 수가 늘고 다음 미완료 항목으로 이동합니다.
8. 3페이지의 악보에서 **마디별 읽기 펼치기**를 확인합니다.
9. 글자 크기와 고대비를 확인합니다. **검수 기록 저장**은 예시 문서의 JSON을 내려받습니다.

키보드: `Tab`/`Shift+Tab` 이동, `Enter` 실행, `Alt+↑/↓` 항목 이동, `Alt+N` 다음 검수 필요 항목, 검수 모드의 `Ctrl+Enter` 확인 완료 후 다음 항목, `Alt+1/2/3` 개요/결과/원본 이동, `Esc` 대화상자 닫기. 스크린리더와 충돌하면 키보드 도움말에서 추가 단축키를 끌 수 있습니다.

## 저장과 범위

- 이 브라우저에 예시의 수정 내용·검수 상태·글자 크기·대비 설정을 저장합니다. 읽기 모드는 새로 열 때마다 기본값입니다.
- **키보드 도움말 → 예시 검수 기록 초기화**에서 내용과 상태를 되돌릴 수 있습니다.
- JSON 내보내기는 시제품의 검수 기록이며 **DAISY 파일이 아닙니다**. 기존 서버에 다시 불러오는 기능도 없습니다.
- 표의 구조화된 행·열과 악보 상세 설명은 예시 데이터입니다. 내용 수정은 대표 인식 문장만 수정합니다.
- 원본은 직접 그린 SVG 예시입니다. 실제 PDF 가져오기, OCR 실행, 모델 호출, 음성 합성, DAISY 패키징은 이번 시제품 범위에 포함되지 않습니다.
- Windows WPF 화면과 Python OCR 서버 코드는 이 시제품 작업에서 변경하지 않습니다.

## 실제 앱에 적용할 때

화면 합의 후 `ReviewWorkspaceView` 및 ViewModel에 적용합니다. 기존 `ReviewBlock`의 `Id`, `PageNumber`, `Content`, `ReviewStatus`, `X/Y/Width/Height`, `PageWidth/PageHeight`를 활용할 수 있습니다. 시제품의 좌표는 800×1120 예시 이미지 기준이며 실제 적용 시 페이지 크기로 정규화해야 합니다. 시제품 JSON을 운영 데이터 형식으로 간주하지 마세요.

검수 상태 대응은 `pending → Pending`, `needs_review → NeedsReview`, `reviewed → Reviewed`입니다. 도표와 악보에는 실제 모델이 반환한 구조·설명을 연결하고, 수정 결과가 DAISY 생성 단계에 전달되는지 별도로 검증해야 합니다.

## 확인 결과

브라우저에서 다음 동작을 확인했습니다.

- 초기 읽기 모드, 검수 모드 전환, 텍스트→이미지 강조, 이미지→텍스트 포커스 이동
- 인식 문장 수정, Ctrl+Enter 완료 처리, 다음 항목 이동, 새로고침 후 수정 내용·완료 수 유지
- Alt+N으로 다음 페이지의 검수 필요 항목 이동
- 필터 빈 결과 및 악보 페이지 전환, 제목 접근성 이름
- 390px 화면에서 본문 200% 확대·고대비 사용 시 문서 가로 넘침 없음
- 실행 중 브라우저 콘솔 JavaScript 오류 없음

이는 화면·키보드·접근성 트리 확인입니다. NVDA 또는 Windows 내레이터의 실제 발화와 DAISY 리더 호환성 검증은 별도로 필요합니다.

## 파일

- `index.html`: 화면 구조, 레이블, 대화상자
- `styles.css`: 반응형 배치, 글자 확대, 고대비, 포커스
- `fixtures.js`: 예시 문서와 원본 이미지 생성
- `app.js`: 선택 동기화, 검수, 수정, 검색, 키보드, 브라우저 저장
