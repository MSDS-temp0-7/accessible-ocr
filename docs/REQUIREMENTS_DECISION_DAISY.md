# DAISY 필수 연동 결정

## 결정 상태

- 상태: 확정
- 적용일: 2026-09-04
- 적용 대상: 점자도서관용 접근형 OCR Windows 앱 전체

## 제품 목적

이 앱은 점자도서관에서 시각장애인용 자료를 제작·검수하기 위한 도구다. 일반 OCR 결과를 확인하는 것에서 끝나지 않고, 원본 PDF를 구조 분석하고 사람이 검수한 뒤 **완성된 DAISY 자료로 내보내는 것**을 핵심 완료 조건으로 삼는다.

## 필수 요구사항

### 1. DAISY 내보내기

- DAISY 출력은 후속 기능이나 선택 연동이 아니라 필수 기능이다.
- 단일 `book.xml` 생성만으로 완료로 보지 않는다.
- 최종 결과에는 DAISY 규격에 필요한 본문, 내비게이션, 메타데이터와 관련 파일을 포함해야 한다.
- 현재 목표 규격은 기존 PRD와 입출력 명세에 따라 DAISY3(Z39.86)로 고정한다. 최종 패키지는 선정한 DAISY3 검증기를 통과해야 한다.

### 2. 검수용 결과물

- OCR·구조 분석 결과를 사람이 수정하고 승인할 수 있어야 한다.
- 검수 상태, 수정 내용, 미확인 항목, 오류 목록을 보존해야 한다.
- DAISY 최종본과 별도로 사람이 읽고 공유할 수 있는 검수 보고서를 내보내야 한다.
- 내부 처리용 `review.json`은 검수 데이터의 한 형태일 뿐, 사용자용 검수 보고서를 대신하지 않는다.

### 3. 스크린리더 접근성

- Windows 내레이터, NVDA 등 외부 스크린리더로 주요 업무를 수행할 수 있어야 한다.
- 모든 주요 화면과 기능은 키보드만으로 조작할 수 있어야 한다.
- 컨트롤의 이름·역할·값·상태를 UI Automation을 통해 제공해야 한다.
- 진행률, 오류, 분석 완료와 같은 상태 변화는 스크린리더에 알림으로 전달해야 한다.
- 포커스 순서, 고대비 모드, 200% 텍스트 확대를 검수 기준에 포함한다.

### 4. 앱 내부 읽어주기

- 앱 내부 TTS 미리 듣기는 스크린리더 호환성과 별개의 기능이다.
- 검수 효율을 높이는 중요 기능으로 설계하되, 외부 스크린리더 접근성을 대체해서는 안 된다.
- 도입 순서는 외부 스크린리더로 전체 검수 흐름을 완료할 수 있게 한 뒤, 본문·수식 대체텍스트 등의 선택 영역 미리 듣기를 추가하는 방향으로 한다.

## 제품 완료 흐름

1. PDF 가져오기
2. OCR 및 문서 구조 분석
3. 페이지·문단·표·그림·수식 영역 검수
4. 접근성 정보와 읽기 순서 수정
5. 검수 보고서 생성
6. DAISY 패키지 생성 및 규격 검증
7. 최종 산출물 저장

## 현재 구현과의 차이

- 현재 생성되는 `book.xml` 및 `review.json` 묶음은 개발 중간 산출물이다.
- 완성 DAISY 패키지 생성과 규격 검증은 아직 구현해야 한다.
- 사용자용 검수 보고서 내보내기도 구현해야 한다.
- 스크린리더용 접근성 속성은 일부 적용되었지만 전체 업무 흐름 검증이 필요하다.
- 앱 내부 TTS 미리 듣기는 아직 구현되지 않았다.

## 문서 해석 우선순위

기존 화면설계서나 개발 문서에서 DAISY·음성 출력이 "후속 연동" 또는 "MVP 제외"로 표현된 경우, 이 결정 문서가 우선한다. 다음 문서 개정 시 해당 표현을 삭제하고 DAISY를 필수 최종 산출물로 통일한다.
