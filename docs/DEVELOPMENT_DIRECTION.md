# 접근형 OCR Windows 앱 개발 방향

## 기준 설계

이 프로젝트의 화면·MVP 범위·접근성 기준은 루트의 `Windows_네이티브_접근형_OCR_화면설계서_v0.1.docx`를 최우선 설계 기준으로 삼는다. 이전의 `접근형 OCR 앱_WF-01~04.png`는 초기 4개 화면 참고 자료로만 유지한다.

제품은 문서를 읽어 주는 챗봇이 아니라, OCR 결과를 접근 가능한 문서 구조로 만들고 사람이 검수하여 배포 가능한 파일로 내보내는 Windows 네이티브 제작·열람 도구다.

## 제품 범위

- 입력: PDF, 이미지, DOCX, HWP
- 구조화: 제목, 문단, 목록, 표·도표, 수식, 악보, 이미지·캡션
- 검수: 원본, AI 제안, 사용자 수정, 신뢰도, 검수 상태와 이력
- MVP 출력: 구조화 DOCX, 접근 가능한 HTML, 검수 보고서
- 후속/연동: DAISY, HWP 직접 출력, 음성 파일, 점자악보, 실시간 공동 편집

현재 시연 환경은 WPF와 분리된 Python FastAPI 보조 프로세스를 같은 PC에서 실행한다. CLOVA OCR만 외부 API를 호출하고 DocLayout-YOLO는 로컬에서 실행한다. 운영 환경에서 로컬 번들 또는 중앙 서버 중 어느 방식으로 배포할지는 아직 확정하지 않는다.

## 구현 현황

| 범위 | 상태 | 구현 내용 |
| --- | --- | --- |
| 로그인·회원가입·권한 | UI/클라이언트 골격 | `/auth/login` 호출, 회원가입 입력 화면, 메모리 토큰, READER·INSPECTOR·VOLUNTEER 역할별 버튼 제어; 실제 인증 서버·DB 대기 |
| WF-01 홈 | 실제 연동 준비 | Windows 파일 선택창으로 멀티페이지 PDF 선택, 정밀/빠른 읽기 |
| WF-02 가져오기 설정 | 구현 | 페이지 범위, 언어, 특수 객체, 처리 정책, 예상 결과 |
| WF-03 분석 진행 | 실제 로컬 연동 | FastAPI Job 업로드·상태 조회, CLOVA/DocLayout 처리, DTBook 패키지 수신 |
| WF-04 검수 작업공간 | 실제 결과 연결 | 페이지·객체 목록 스크롤, OCR 입력 페이지 이미지, 유형별 좌표 박스, 목록·오버레이·검사 패널 선택 연동 |
| WF-05 표·도표 상세 | UI 구현 | 실제 표 구조(F2) 연동 대기 |
| WF-06 수식 상세 | UI 구현 | MathML·alttext·수식 영역(F4) 연동 대기 |
| WF-07 악보 상세 | UI 구현 | MusicXML·점자악보(F5) 연동 대기 |
| WF-08 검수·내보내기 | 실제 결과 연동 | 결과 패키지 수신 전에는 빈 상태만 표시; DTBook 패키징(F11) 및 DOCX/HTML 변환 API 연동 대기 |

앱 셸은 분석 화면 밖에서도 현재 Job의 진행률·완료·오류 상태를 표시한다.
사용자는 좌측 메뉴 또는 상단의 `진행 중 작업` 버튼으로 언제든 분석 화면에
복귀할 수 있다. Job 실행 중에는 새 PDF 선택과 중복 분석 시작을 잠가 현재
작업이 화면 이동 때문에 유실되거나 교체되지 않게 한다.

현재 앱은 실제 PDF를 로컬 `daisy_ocr.server`에 보내고 결과를 표시한다. API가 꺼져 있거나 CLOVA 설정이 없으면 분석은 오류 상태를 표시하며 가짜 성공 결과를 만들지 않는다. API 주소와 경로는 `src/AccessibleOcr.Desktop/appsettings.json`에서 관리한다.

## 기술 구조

| 영역 | 선택 | 역할 |
| --- | --- | --- |
| 데스크톱 UI | WPF + .NET 8 | Windows 네이티브 UI, XAML, UI Automation |
| 화면 패턴 | MVVM | View, ViewModel, 데이터 서비스를 분리 |
| OCR 연동 | HTTP 비동기 Job API | PDF 업로드, 상태 조회, 결과 패키지 수신 |
| 로컬 처리 | Python 3.11 + FastAPI | CLOVA 호출, DocLayout-YOLO 추론, 결과 병합·직렬화 |
| 결과 형식 | DAISY3 DTBook + review sidecar | `book.xml`은 구조·판독 순서, `review.json`은 신뢰도·픽셀 좌표 |
| 로컬 캐시 | SQLite (후속) | 임시 수정본, 최근 프로젝트, 작업 재개 |
| 배포 | MSIX (후속) | 기관 배포, 업데이트, Windows 알림 |

```text
View (XAML)
  -> ViewModel (상태·명령·접근성 메시지)
    -> Service interface (문서·분석·내보내기)
      -> HTTP OCR 파이프라인 구현체
```

View는 API, 파일 시스템, OCR 엔진을 직접 호출하지 않는다. ViewModel은 구체 구현체가 아닌 서비스 인터페이스를 사용한다.

## 화면과 사용자 흐름

```text
WF-01 홈
  -> WF-02 가져오기 설정
  -> WF-03 분석 진행
  -> WF-04 검수 작업공간
      -> WF-05 표·도표 상세
      -> WF-06 수식 상세
      -> WF-07 악보 상세
  -> WF-08 검수·내보내기
```

- 분석 완료 후에는 자동 전환하지 않는다. 사용자가 `검수 작업공간 열기`를 선택한다.
- 분석 중 다른 화면으로 이동해도 Job과 진행률 조회는 계속된다. `새 프로젝트`는
  현재 화면만 홈으로 바꾸며 진행 중인 Job을 취소하거나 초기화하지 않는다.
- 앱 또는 로컬 API를 종료한 뒤 Job을 복구하는 기능은 DB·로컬 캐시 구현 후 제공한다.
- 파일을 선택하거나 OCR 결과 패키지를 받기 전에는 예시 문서명, 객체 수, 검수 건수를 표시하지 않는다. 빈 상태 안내만 보여 준다.
- 기본 읽기 단위는 문단과 특수 객체 개요다.
- 객체 상세는 Enter로 진입하고 Esc로 개요에 복귀한다.
- 검수 중에는 원문과 사용자 수정 내용을 명시적으로 구분한다.
- 미확인 항목이 있어도 내보내기를 막지 않고 결과와 검수 보고서에 상태를 표시한다.

## 접근성 계약

- 모든 핵심 흐름은 키보드만으로 완료할 수 있어야 한다.
- `Tab`/`Shift+Tab`은 컨트롤 이동, `Enter`는 상세·기본 동작, `Esc`는 상세 종료에 사용한다.
- `Alt+1`, `Alt+2`, `Alt+3`은 문서 개요·객체 목록·검수 목록 이동을 목표로 한다.
- `F6`은 좌측 개요 → 중앙 본문 → 우측 검사 패널을 순환한다.
- 모든 컨트롤은 보이는 라벨과 같은 UI Automation 이름·역할·값·상태를 제공한다.
- 진행률·발견 객체·오류는 중복을 합친 라이브 알림과 화면 로그로 제공한다.
- 색상 외에 텍스트와 상태로 정상·검토 필요·오류·검수 완료를 전달한다.
- 200% 텍스트 확대, Windows 고대비, 포커스 사각형, Narrator를 완료 기준에 포함한다.
- 원본 OCR 오버레이가 생기더라도 동일 정보는 접근 가능한 트리·목록·편집기로 탐색 가능해야 한다.
- 중앙 원본 미리보기는 가로·세로 스크롤을 제공하며, 박스만으로 정보를 전달하지 않는다. 같은 객체를 왼쪽 목록과 오른쪽 검사 패널에서도 선택·확인할 수 있어야 한다.

## 공통 데이터 규칙

- 좌표: `x`, `y`, `width`, `height`의 0~1 정규화 값
- OCR API 사이드카 원본 좌표: `page_index`(0-based) + 픽셀 `bbox: [x, y, w, h]`. UI 렌더링 시 페이지 크기로 정규화한다.
- 객체 유형: `Text`, `Table`, `Graph`, `Math`, `Music`, `Image`
- 검수 상태: `Pending`, `Reviewed`, `NeedsReview`
- 문서 상태: `Uploaded`, `Processing`, `AiDraft`, `InReview`, `ReviewNeeded`, `Completed`, `Exporting`, `ReadyForDownload`, `Failed`
- 수정 요청에는 `revision`을 포함하여 동시 수정 충돌을 감지한다.

## Git 작업 규칙

- `main`에는 빌드·검증된 코드만 병합한다.
- 작업은 `feature/<기능명>` 브랜치에서 하고, 한 커밋에는 한 가지 의도를 담는다.
- 커밋 메시지는 동사로 시작한다. 예: `feat: add math detail workspace`.
- API 계약 변경은 `docs/`와 코드 모델을 같은 변경 단위에 포함한다.
- `bin/`, `obj/`, 개인 IDE 설정, 비밀값, 로컬 DB, 임시 렌더 결과는 커밋하지 않는다.
