# 로그인·회원가입·권한 연동

최종 갱신: 2026-08-12

## 현재 구현

- 앱 시작 시 로그인 화면 표시
- `POST /auth/login` HTTP 호출 골격
- 로그인 토큰의 메모리 보관과 로그아웃 시 제거
- `READER`, `INSPECTOR`, `VOLUNTEER` 역할 모델
- 역할별 업로드·검수·내보내기 UI 제어
- 로그인 화면에서 회원가입 화면으로 이동
- 회원가입 이름·이메일·비밀번호·계정 유형 입력과 클라이언트 형식 검증

회원가입은 현재 화면 골격만 구현되어 있다. 입력값은 서버로 전송하거나 파일·DB에 저장하지 않으며, 성공 계정도 만들지 않는다.

## 회원가입 화면 입력 모델

코드 모델: `Models/RegistrationDraft.cs`

```text
name
email
password
requestedRole: READER | VOLUNTEER
```

`INSPECTOR`는 사용자가 회원가입 화면에서 선택할 수 없다. 기관 검수자 권한은 추후 관리자 승인 또는 별도 초대 절차로 부여한다.

## 추후 서버 API 연결 자리

회원가입 엔드포인트는 기존 명세에 없으므로 아직 경로와 응답을 확정하지 않았다. 통합 서버 계약이 정해지면 다음 순서로 연결한다.

```text
SignUpView
  -> SignUpViewModel
  -> IRegistrationService (추가 예정)
  -> 통합 API 회원가입 엔드포인트
  -> 사용자 DB
```

확정이 필요한 항목:

1. 회원가입 URL과 HTTP 메서드
2. 이메일 인증 여부
3. 자원봉사자 본인인증 및 승인 절차
4. 중복 이메일·비밀번호 정책 오류 형식
5. 가입 직후 로그인 여부
6. 관리자에 의한 `INSPECTOR` 권한 부여 방식

## DB 연결 시 필수 원칙

- 비밀번호 원문을 DB, 로그, 설정 파일에 저장하지 않는다.
- 서버에서 검증된 비밀번호 해시만 저장한다.
- 이메일 중복과 역할 부여는 서버가 검사한다.
- 클라이언트의 버튼 비활성화는 보안 검사가 아니다.
- 모든 보호 API는 서버에서 JWT와 역할을 다시 검증한다.
- Refresh Token 저장·폐기·재발급 정책을 별도로 정한다.

## 개발 미리보기

Debug 빌드의 개발 미리보기는 로그인 이후 UI 확인을 위한 임시 진입이다. 실제 사용자, 토큰, 권한 또는 회원가입 상태를 만들지 않으며 Release 빌드에서는 표시하지 않는다.
